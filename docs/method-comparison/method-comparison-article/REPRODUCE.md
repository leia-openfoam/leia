# Reproducing every measurement in `methodComparison.tex`

Version-controlled beside the manuscript. Every number, table and figure this
paper reports is produced by a committed study config and a committed script;
nothing is curated by hand. If a command below does not reproduce the committed
CSV, that is a bug in the repository and not a missing step.

Each study is **one command**. All of them are independent and can be run in any
order, except where "must be re-run together" says otherwise.

---

## 0. Environment

```bash
# OpenFOAM v2512, source-built. On the WSL laptop and on Lichtenberg alike:
source $HOME/OpenFOAM/OpenFOAM-v2512/etc/bashrc
git clone git@github.com:leia-openfoam/leia.git && cd leia
./Allwmake
```

Python side: `snakemake` (v9.x), `numpy`, `matplotlib`, `pandas`. Nothing else.
**Every OpenFOAM, Python and Snakemake command runs under Linux/WSL, never a
Windows shell.**

Two run backends, identical study definitions, selected purely by profile:

```bash
snakemake --workflow-profile profiles/local --configfile config/<study>.yaml   # mpirun
snakemake --workflow-profile profiles/slurm --configfile config/<study>.yaml   # one sbatch per case
```

Add `-n` for a dry run (prints the DAG without executing), `-p` to see the shell
commands. On a cluster, submit the orchestrator as a job rather than running it
on a login node — see §5.

---

## 1. What each study measures, and the command

Outputs land in `studies/<study>/`: one directory per arm, plus
`<study>_database.csv` (every column) and `<study>_errors.csv` (the convergence
columns). The tables in §2 are curated from those.

| study | measures | resolutions | cost |
|---|---|---|---|
| `domainSizeControl10R`, `domainSizeControl6R`, `domainSizeControl4R` | whether truncating the far field at FIXED h is inert; three box sizes L = 10R/6R/4R at two matched cell sizes | h = 1e-4, 5e-5 | ~1 core-h total |
| `cellCentreInverseFiltered` | the 2D ladder, cell-centre parallel-surface inverse x psi filter, theta = 0.05 and 0.2 | N = 64/128/256 | ~15 core-h |
| `cellCentreInverseFiltered512` | the 2D ladder's fourth point | N = 512 | 79 core-h |
| `stationaryDroplet3Dwide` | the 3D ladder on the certified L = 6R box | N_L = 60/76/95/120 | 565 core-h |
| `stationaryDroplet3Dwide120` | rerun of the finest 3D arm after a wall-clock kill | N_L = 120 | 371 core-h |
| `stationaryDroplet3DwideNoK` | the SAME 3D ladder with the Gaussian-curvature term of the inverse switched off | N_L = 60/76/95 | ~193 core-h |
| `interFoamDroplet2D`, `interFoamDroplet3D` | the interFoam reference arm on the same droplet | matched to the above | ~100 core-h total |
| `cellCentreInverseDroplet`, `cellCentreInverseDroplet3D` | the same delivery UNFILTERED, isolating the filter's contribution | N = 64/128/256; N_L = 32/64 | ~40 core-h |
| `capillaryEnvelope`, `capillaryEnvelopeKinematic` | transport order x filter strength: the operating envelope, coupled and kinematic | 28 arms | ~120 core-h |

```bash
# any single study, locally
snakemake --workflow-profile profiles/local --configfile config/domainSizeControl6R.yaml
```

**Read the config header before the results.** Every config states what it
measures, what is held fixed, and the PREDICTIONS recorded before the run —
including the failure modes that would disqualify the arm. Several predictions in
this campaign were falsified by their own runs; the headers say so rather than
being edited afterwards.

**Must be re-run together:** the three `domainSizeControl*` studies (the verdict
is a comparison ACROSS them, and a monotone-in-L wall effect cannot be
distinguished from scatter with fewer than three box sizes), and
`stationaryDroplet3Dwide` + `stationaryDroplet3Dwide120` (one ladder split across
two study dirs, see that config's header for why).

## 2. From study output to the curated tables

Curated CSVs live in `data/tables/`. Each is regenerated by one command.

```bash
# domain-size control -> data/tables/domain_size_control.csv, and the VERDICT
python3 workflow/scripts/domain_size_control.py \
    --studies-root studies \
    --out docs/method-comparison/method-comparison-article/data/tables/domain_size_control.csv \
    domainSizeControl10R domainSizeControl6R domainSizeControl4R

# the coupled ladders (2D + 3D, all arms) -> data/tables/wide_ladder_coupled.csv
python3 workflow/scripts/make_wide_ladder_table.py \
    --out docs/method-comparison/method-comparison-article/data/tables/wide_ladder_coupled.csv \
    studies/cellCentreInverseFiltered studies/cellCentreInverseFiltered512 \
    studies/stationaryDroplet3Dwide studies/stationaryDroplet3Dwide120 \
    studies/stationaryDroplet3DwideNoK

# convergence orders: GLOBAL least-squares fits, with R^2 and the pairwise values
python3 workflow/scripts/convergence_order_fit.py \
    docs/method-comparison/method-comparison-article/data/tables/wide_ladder_coupled.csv
```

`domain_size_control.py` exits non-zero if any gate is violated, so it is usable
as a test and not only as a table generator.

**On reading the orders.** `convergence_order_fit.py` prints the global fit
first, deliberately. A pairwise order uses two points and inherits both their
noise: this ladder produced +2.43 and +7.59 for a method that is at most second
order, which is not an order but the signature of a coarse point outside the
asymptotic regime. The fit also reports the exponent WITHOUT the coarsest point,
so the reader can see how much the answer depends on which points are trusted.
And the order is defined against the cell size h — halving h and halving the
error is FIRST order; second order quarters it. Dimension does not enter that
statement; it matters only if one indexes by cell count instead, since
cells ~ h^-d.

## 3. Static gates (no flow solve)

The curvature models are scored on exact interfaces before any coupled run.
These are seconds to minutes and are the first thing to run after a build.

```bash
# curvature accuracy on exact interfaces, one config per shape, every delivery
snakemake --workflow-profile profiles/local --configfile config/faceCurvatureDroplet2D.yaml
snakemake --workflow-profile profiles/local --configfile config/faceCurvatureEllipse2D.yaml
snakemake --workflow-profile profiles/local --configfile config/faceCurvatureSphere3D.yaml
snakemake --workflow-profile profiles/local --configfile config/faceCurvatureEllipsoidPsi2D.yaml

# the parallel-surface inverse as pure arithmetic: sphere, cylinder, torus (where
# the two principal curvatures differ and K < 0 on the saddle side), both signs of
# the offset, and the K = 0 reduction identity. No mesh. Exits non-zero on any
# mismatch, so it belongs in a build check.
leiaTestParallelSurfaceInverse
```

The ellipse and ellipsoid gates are the ones that matter for a claim about
VARYING curvature: on the constant-curvature circle and sphere the exact
non-gradient content of the capillary force vanishes identically, so a delivery
can score second order there and first order wherever curvature varies along the
interface. Both numbers belong in the paper.

## 4. Reproducing a single arm by hand

Useful when debugging one resolution without the workflow.

```bash
cd cases/stationaryDroplet2D          # or interFoamDroplet2D, ...
# render the @!TOKEN!@ templates with the values you want, then:
./Allrun.sh
```

The token defaults live in `cases/<Case>.parameter` beside the case directory,
with repository-wide fallbacks in `cases/default.parameter`. A study config's
`axes_override` replaces them. Derived tokens (`MAX_DELTA_T`, `HALF_END_TIME`,
`DOMAIN_HALF_LENGTH`) are computed in `workflow/scripts/materialize.py` and must
not be set by hand.

**The capillary time step follows h, not the cell count.** `MAX_DELTA_T` is
evaluated at the reference-equivalent cell count
`nRef = CAPILLARY_REF_LENGTH/h` with `h = DOMAIN_LENGTH/N_CELLS`, because
`dt < sqrt(rho h^3 / 2 pi sigma)` is set by the cell size. On the reference
0.01 m box this is identical to `CAPILLARY_DT_COEFF/N_CELLS^1.5`; on a truncated
box the cell-count form would hand back a step `(0.01/L)^1.5` too large.

## 5. Cluster (Lichtenberg)

```bash
ssh <user>@lcluster5.hrz.tu-darmstadt.de
cd <repo>                       # a working copy on the parallel file system
sbatch --export=ALL,STUDY=<study> run-studies.sbatch     # one study
```

Every job **must** set `--mem-per-cpu` (the slurm profile does). Size `--time` to
measured pace: a driver must outlive its children, and `solve_runtime` in the
config is the per-arm limit in minutes. **A wall-clock kill loses the arm's
metrics CSV** — snakemake deletes a failed rule's declared outputs — so an
under-sized limit costs the whole run, not the tail. The measured pace for the
level-set solver is ~1.0e-5 core-s per cell-step in 2D and 2.0e-5 in 3D, rising
to 3.0e-5 on meshes of ~1.7e6 cells where the pressure solve needs more
coarsening levels; interFoam is roughly 3x cheaper per cell-step.

Resuming is free: snakemake skips arms whose outputs exist, so re-submitting
after any interruption continues where it stopped.

## 6. Provenance recorded per arm

Every arm writes `case_params.json` containing the full token vector, the run
date, `np`, and the git commit of the code that built it — with `-dirty` appended
if `src/`, `applications/`, `workflow/`, `cases/` or `config/` had uncommitted
changes. A curated table whose arms show `-dirty` is not reproducible, and that
is visible without asking anyone.
