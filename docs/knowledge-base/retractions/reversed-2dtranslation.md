# "2Dtranslation is a uniform one-way translation": the case was a reversed flow (2026-09-29)

> VOIDED 2026-09-29. The claim was that `cases/2Dtranslation` carries a circle one way at U = (1,0,0), so that "EVERY error this case reports is semi-Lagrangian transport error alone" ([2Dtranslation.parameter L1-L3 at 8867581](https://github.com/leia-openfoam/leia/blob/8867581/cases/2Dtranslation.parameter#L1-L3)). The comment said: "The circle starts at x = 0.25 and travels to x = 0.75" ([L28-L29 at 8867581](https://github.com/leia-openfoam/leia/blob/8867581/cases/2Dtranslation.parameter#L28-L29)). The measurement: commit cd97e6da (2026-09-01) made the case from `2Dvortex` and dropped the line `oscillation @!OSCILLATION!@;` ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4176-L4178)). The velocity model then uses its defaults: `oscillation` true and `tau` = `endTime` ([velocityModel.C L49-L50](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/src/leiaLevelSet/velocityModel/velocityModel.C#L49-L50), `src/leiaLevelSet/velocityModel/velocityModel.C`). So U(t) = cos(pi t/T) (1 0 0), and the circle came back to its start at T. The recorded runs show it: U = (0.034 0 0) at t = 0.2446 and (-0.99991 0 0) at t = 0.4979; the centroid moves 0.2500, 0.4082, 0.2502 ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4178-L4182)). The case had no `psiEnd`, so the metrics compared the fields at T with the initial fields ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4179-L4180)). The solver did not say so, and this silent fallback hid the reversal for four weeks ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4195-L4197)). Scope of the void: every number of the case before the fix, in every arm. That is `kinematicTranslation2D`, `coneBoundMesh2Dtranslation` with its four arms, `advConv2Dtranslation`, and the 2Dtranslation rows of the regression and bit-identity gates ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4182-L4186)). Two statements of `METHOD.md` fall with the data: "the unbounded translation saturates at N = 256" and "the cone bound is better at the coarsest rung" ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4187-L4188)). The fixed case runs one way, with an exact end reference and psi zeroGradient on all four patches ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4190-L4199)). One way, the unbounded scheme converges at orders 2.90, 2.16, 1.86 over N = 32 to 256 ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4238-L4243)). The cone bound is 14.1 times worse than no bound at N = 64 ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4248-L4250)).

## Two more setup errors, found during the repair: fixed psi values on a patch

The approved plan put the exact psi on all four patches. STATUS records: "that was my recommendation, and I was wrong" ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4201-L4204)). The SL fit reads every physical patch value as a stencil datum (`SL_STENCIL_BOUNDARY_FACES include`, the default). A serial probe ran four boundary variants (`workflow/scripts/translation_bc_probe.sh` and `translation_bc_probe_scan.py`, [probe L1-L17](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/workflow/scripts/translation_bc_probe.sh#L1-L17)). `E_GEOM_ALPHA_REL` at T:

| psi on left (inflow) / right (outflow) / top, bottom | N = 128, CFL 0.5 | N = 256, CFL 0.5 | N = 128, CFL 1 |
|---|---|---|---|
| exact / exact / exact | 1.72e-03 | 1.98e-02 (outflow edge 4.5e+05) | 1.79 |
| exact / zeroGradient / exact | 1.61e-03 | 4.44e-04 | 1.79 |
| exact / zeroGradient / zeroGradient | 1.61e-03 | 4.44e-04 | 1.79 |
| zeroGradient everywhere (committed) | 1.61e-03 | 4.44e-04 | 2.15e-03 |

The table is [STATUS 11.19 item 3](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4206-L4213), MEASURED.

1. The exact value on the OUTFLOW patch. The outflow-edge error grows by a factor of about 1.1 per step (N = 64 to 256, CFL 0.5). It reaches 4.5e5 at T at N = 256 and makes 96 false zero-set cells. It corrupted the `none` N = 256 rung of the first re-run (`E_GEOM_ALPHA_REL` order -3.53); those trees are `*_VOID_outflowDirichlet_20260929` ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4215-L4218)).
2. The exact value on the INFLOW patch at CFL 1. There the departure point of the first cell column lies outside the domain, and 2246 false zero-set cells appear in the inflow region; those trees are `*_VOID_inflowDirichlet_20260929` ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4218-L4221)).
3. zeroGradient on all four patches is stable in both: the outflow-edge error is 1.7e-03 at N = 256 (CFL 0.5) and 8.8e-04 at N = 128 (CFL 1) ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4221-L4222)). No production case gives psi a fixed value, so no production run is affected ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4222-L4223)).
4. The consequence for this case: the inflow region x < t keeps psi0(0, y) >= 0.10. It has no zero crossing, so the interface metrics are unaffected, but the GLOBAL gradient metrics measure that frozen region ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4223-L4225)). The field file states the two measurements (4.5e5 at T at N = 256, 2246 false zero-set cells) and tells the reader to use the band metrics ([0.org/psi L21-L41](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/cases/2Dtranslation/0.org/psi#L21-L41), `cases/2Dtranslation/0.org/psi`).
5. `CLAUDE.md` and `AGENTS.md` carry the corollary "never give psi a fixed value on a patch", because of `SL_STENCIL_BOUNDARY_FACES include` ([CLAUDE.md](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/CLAUDE.md#L528-L532)). The SL treatment of fixed psi data is an open question for the SL session ([[sessions/sl-session-handover]]).

The repair gate `config/translationRepairGate2D{serial,par4}.yaml` was pre-registered before each run. Its header records four runs. The first failed line 4 (`E_VOL_ALPHA_REL` = 1.6e-2 at t = 0), because the end reference came from a non-pristine `0/` (`*_VOID_endRefNonPristine_20260929`). The second run had the exact value on all four patches (`*_VOID_outflowDirichlet_20260929`), and RE-RUN 2 had it on the inflow and no-flow patches (`*_VOID_inflowDirichlet_20260929`), so both are void although they passed their lines ([serial gate L23-L69](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/config/translationRepairGate2Dserial.yaml#L23-L69)). STATUS counts three runs, the first two void ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4227-L4228)). RE-RUN 3, zeroGradient on all four patches, passes every line on both indicator arms: U = (1 0 0) at every write; 108 steps; centroid at T (0.74972, 0.50000); `E_VOL_ALPHA_REL` at t = 0 1.65e-14; `E_GEOM_ALPHA_REL` 2.000000 at t = 0 and 7.210e-03 at T; np 4 against serial 2.7e-12 column-scaled; outflow edge 5.92e-03 at t = 0.2486 and 6.90e-03 at T ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4228-L4232), [par4 gate L83-L93](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/config/translationRepairGate2Dpar4.yaml#L83-L93)).
