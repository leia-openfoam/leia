# The kinematic advection cases

> Verdict (2026-09-29). The kinematic cases prescribe the velocity, so no force, pressure or curvature enters the loop and every error is transport error ([2Dtranslation.parameter L1-L3](https://github.com/leia-openfoam/leia/blob/d1e3414/cases/2Dtranslation.parameter#L1-L3), [[models/level-set-advection]]). On the 2D vortex the shape-error order of the quadratic semi-Lagrangian scheme is 2.97 at CFL 1/2 and 2.59 at CFL 1. On the 3D shear it is 2.95 on hex and 3.28 on polyhedra, and on the filament-limited 3D deformation 1.36 and 1.46 ([SL article L1371-L1430](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/semi-lagrangian-level-set/sl-level-set-article/semiLagrangianLevelSet.tex#L1371-L1430)). The polyhedral orders ran with the clip on, which production no longer uses ([uncachedConv3DshearPoly.yaml L30-L38](https://github.com/leia-openfoam/leia/blob/d1e3414/config/uncachedConv3DshearPoly.yaml#L30-L38), [[concepts/value-bounds-and-clips]]). The 2D vortex and the 3D deformation have u = 0 on every wall. Such a gate never moves the foot in the wall cells, so it does not test the boundary stencils ([CLAUDE L516-L526](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L516-L526)). Two polyhedral defects of 2026-09-05 hid in exactly those cells ([STATUS L1584-L1593](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L1584-L1593), [L1900-L1915](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L1900-L1915)). The regression set names `2Dtranslation` as the only O(1)-displacement gate ([CLAUDE L590-L594](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L590-L594), [[concepts/advection-regression-set]]). Until 2026-09-29 its dictionary had no `oscillation` entry, so the base default reversed the translation: the circle travelled at most about 0.16 and returned. The recorded runs confirm it, so every earlier number of the case is void ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4176-L4182), [[retractions/reversed-2dtranslation]]). One way, `E_GEOM_ALPHA_REL` converges at orders 2.90, 2.16, 1.86 over N = 32 to 256 ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4238-L4243)).

## What it is

Each case sets a `velocityModel` in `system/fvSolution`. The solver takes the cell velocity and the face flux from the analytic field. It does so on internal faces and on every non-coupled boundary face ([velocityModel.C L117-L232](https://github.com/leia-openfoam/leia/blob/d1e3414/src/leiaLevelSet/velocityModel/velocityModel.C#L117-L232), `src/leiaLevelSet/velocityModel/velocityModel.C`). With `oscillation on`, the solver multiplies both by `cos(pi t / tau)`, with `tau = endTime` by default, so the interface returns to its initial state at `t = T` ([velocityModel.C L49-L50](https://github.com/leia-openfoam/leia/blob/d1e3414/src/leiaLevelSet/velocityModel/velocityModel.C#L49-L50), [L80-L105](https://github.com/leia-openfoam/leia/blob/d1e3414/src/leiaLevelSet/velocityModel/velocityModel.C#L80-L105)). The default of that entry is `on` ([velocityModel.C L49](https://github.com/leia-openfoam/leia/blob/d1e3414/src/leiaLevelSet/velocityModel/velocityModel.C#L49)). The velocity formulas are in [prescribedVelocityModels.C L61-L206](https://github.com/leia-openfoam/leia/blob/d1e3414/src/leiaLevelSet/velocityModel/prescribedVelocityModels.C#L61-L206).

The error metrics are the same in every case. `E_GEOM_ALPHA = sum_c V_c abs(alpha_c - alpha0_c)`, relative to `sum_c V_c alpha0_c`; `E_VOL_ALPHA_REL` is the relative phase-volume change; `E_BOUND_ALPHA` is the largest over- or undershoot of alpha ([advectionErrors.H L48-L79](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/solvers/leiaSemiLagrangeLevelSetFoam/advectionErrors.H#L48-L79), [advectionErrorsCsv.H L31-L55](https://github.com/leia-openfoam/leia/blob/d1e3414/src/leiaLevelSet/advectionErrorsCsv.H#L31-L55)). `alpha0` is the initial field unless the case supplies `alphaEnd`. So the shape error is an error only for a reversed flow ([errorCalculation.H L93-L118](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/solvers/leiaSemiLagrangeLevelSetFoam/errorCalculation.H#L93-L118), [aggregate.py L316-L329](https://github.com/leia-openfoam/leia/blob/d1e3414/workflow/scripts/aggregate.py#L316-L329)). Since 2026-09-29 `write_end_reference.py` writes `psiEnd` and `alphaEnd` for `2Dtranslation`, and the three kinematic solvers print which error reference they use ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4190-L4197)). The gradient error comes from a function object. On a reversed flow read the gradient at T/2, the shape at T and the volume at both ([CLAUDE L507-L514](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L507-L514), [README L151-L158](https://github.com/leia-openfoam/leia/blob/d1e3414/workflow/README.md#L151-L158), [[concepts/error-vector-and-read-out-instants]]).

## Why it matters

The research loop puts kinematic transport before any coupled run, because a coupled failure is otherwise ambiguous between transport and force ([CLAUDE L474-L497](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L474-L497)). `2Dtranslation` exists for that reason. The coupled translating droplet failed while the stationary droplet was clean, and no translating kinematic rung had run ([kinematicTranslation2D.yaml L4-L15](https://github.com/leia-openfoam/leia/blob/d1e3414/config/kinematicTranslation2D.yaml#L4-L15)). Its result of 2026-09-01 exonerated the transport. The coupled droplet runs at an interface Courant number of 0.0059, more than 40 times below the cheapest arm of the gate ([L70-L75](https://github.com/leia-openfoam/leia/blob/d1e3414/config/kinematicTranslation2D.yaml#L70-L75)). That result ran on the reversed flow and is void, and the record does not restate the exoneration from the one-way data (not recorded, [[retractions/reversed-2dtranslation]]). Every change to the advection path re-runs three of these cases at three resolutions each ([CLAUDE L583-L598](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L583-L598)).

## The boundary-stencil trap

A discretisation error of the form coefficient x displacement^n needs a gate with O(1) displacement in the cells it can affect ([CLAUDE L516-L526](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L516-L526)). On a wall with u = 0 the foot stays on the cell centre, and the error is invisible. The record has four defects of this kind:

1. The quadratic fit on cfMesh's boundary-layer polyhedra. The offending cells have 10 point neighbours for 9 coefficients, condition numbers 3e7 to 6e12 and coefficients 3e2 to 3e8. The fit is exact at zero displacement and wrong by coefficient x (U dt)^2 at the foot ([STATUS L1584-L1593](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L1584-L1593)). The first translating polyhedral case put the far field 1.4 h wrong after one step and diverged at step 3 ([CLAUDE L522-L523](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L522-L523)). The fix is the pivot tolerance `SL_QUAD_PIVOT_TOL 0.3` ([DP L1060-L1081](https://github.com/leia-openfoam/leia/blob/d1e3414/cases/default.parameter#L1060-L1081), [[models/sl-reconstruction]]).
2. Boundary faces as stencil data. With `psi zeroGradient`, each boundary face gives the cell's own value at h/2 with a large weight, and the fit's normal gradient collapses. The level set then moves normal to an inflow or outflow boundary at only 8 % to 49 % of the exact rate ([DP L1083-L1100](https://github.com/leia-openfoam/leia/blob/d1e3414/cases/default.parameter#L1083-L1100), [STATUS L1900-L1915](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L1900-L1915)).
3. The far-field checkerboard in the small one-sided outlet cells. The sigma = 0 coupled control in a uniform stream is the missing kinematic gate, and it fails at step 508 ([STATUS L1840-L1852](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L1840-L1852), [[concepts/polyhedral-fit-amplification]]).
4. Fixed psi values on a patch, found on the one-way `2Dtranslation` on 2026-09-29. The fit reads the patch value as a stencil datum (`SL_STENCIL_BOUNDARY_FACES include`). The exact psi on the outflow patch grew the edge error by a factor of about 1.1 per step, to 4.5e5 at T at N = 256. The exact psi on the inflow patch failed at CFL 1, where the departure point leaves the domain ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4215-L4221)). zeroGradient is stable in both, and `CLAUDE.md` now says: never give psi a fixed value on a patch ([CLAUDE.md, the corollary on `SL_STENCIL_BOUNDARY_FACES include`](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/CLAUDE.md#L528-L532)).

The velocity on the walls of each case is in the table above. Only the translations, the rotation, the 3D shear on its top and bottom walls and the contact-line cases move the wall cells.

## Decisions

- The standing advection regression set has three rungs: `2Dvortex` or `2Dtranslation` on hex, `3Dshear` on hex and `3Dshear` on pMesh. Each runs at three resolutions, and an inert change must be byte-identical there ([CLAUDE L583-L598](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L583-L598), [[concepts/advection-regression-set]]).
