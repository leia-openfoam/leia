# The static curvature gates: circle, ellipse, ellipsoid

> Verdict (2026-09-29). The static gates score the delivered curvature on an exact interface without flow, on one rank, with one curvature evaluation per resolution ([STATUS 3](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L380-L383)). The circle cannot rank the inverse-based deliveries: all of them are second order there, 1.97 to 2.00 ([PCS 14.1](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L1144-L1145)). The 2:1 ellipse, with an exact curvature from 250 to 2000 1/m, decides accuracy. There the per-face inverse keeps order 1.98. Both one-value-per-cut-cell deliveries fall to 1.02 and 1.03 and are 21 times less accurate at N = 512 ([PCS 12](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L1004-L1018)). That result retracted the cell-mean delivery ([[retractions/cell-mean-delivery-adoption]]). On the sphere the Gaussian-curvature-aware inverse converges at `h^1.95`, against `h^1.02` without K ([RM](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/capillary-level-set-research-roadmap.md#L1378-L1388)). A new delivery passes only with `G h^2 <= 0.65` and an L2 order `>= 1.9` on the ellipse gate, not on the circle ([STATUS 7](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L2703-L2706)). The production delivery since 2026-09-01, `cellCentreInverse`, was never scored on the ellipse gate ([METHOD 8.1](https://github.com/leia-openfoam/leia/blob/d1e3414/METHOD.md#L393)), and the record holds no result of the ellipsoid gate.

## What it is

**The gates.** Each gate is a study config that runs a test application on an initialised case, one curvature evaluation per resolution, on one rank:

| gate | config | case | ladder | exact curvature |
|---|---|---|---|---|
| circle, cell curvature | [`curvatureDroplet2D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/curvatureDroplet2D.yaml#L1-L32) | `stationaryDroplet2D` | N = 32 to 512 | 1/R = 1000 1/m |
| circle, face curvature | [`faceCurvatureDroplet2D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/faceCurvatureDroplet2D.yaml#L29-L41) | `stationaryDroplet2D` | N = 32 to 512 | 1/R |
| 2:1 ellipse, signed distance | [`faceCurvatureEllipse2D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/faceCurvatureEllipse2D.yaml#L1-L54) | `ellipseDroplet2D` | N = 64 to 512, orders on N >= 128 | 250 to 2000 1/m |
| foliation: the same ellipse, psi as the quadratic form | [`faceCurvatureEllipsoidPsi2D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/faceCurvatureEllipsoidPsi2D.yaml#L1-L48) | `ellipseDroplet2D` | N = 64 to 512 | as above |
| sphere | [`faceCurvatureSphere3D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/faceCurvatureSphere3D.yaml#L1-L41) | `3Ddeformation` | N = 32 / 50 / 80 / 128 | 2/R |
| triaxial ellipsoid | [`faceCurvatureEllipsoid3D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/faceCurvatureEllipsoid3D.yaml#L1-L36) | `ellipsoidDroplet3D` | N = 32 / 50 / 80 / 128 | varies |

The circle gate `curvatureDroplet2D` is a config on the stationary case, not a case folder. `make curvature` runs it through [`workflow/Snakefile.curvature`](https://github.com/leia-openfoam/leia/blob/d1e3414/workflow/Snakefile.curvature#L1-L58) and writes `curvature_error.{csv,tex}` and `sl_curvature_error.png` into the SL theme. The ellipse has the semi-axes 2 mm and 1 mm in the 10 mm box, so `kappa(theta) = a b/(a^2 sin^2 theta + b^2 cos^2 theta)^(3/2)`. Its tightest radius of curvature is 0.5 mm, 3.2 cells at N = 64; N = 64 is a trend point only ([`ellipseDroplet2D.parameter`](https://github.com/leia-openfoam/leia/blob/d1e3414/cases/ellipseDroplet2D.parameter#L1-L32)). The ellipsoid has the half-axes 0.21, 0.15 and 0.107, with the volume of the sphere gate's R = 0.1503. It runs the signed distance and the implicit function ([`faceCurvatureEllipsoid3D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/faceCurvatureEllipsoid3D.yaml#L1-L36)).

**The two numbers.** Every gate reports two numbers per delivery:

1. Accuracy: the `abs(Sf)`-weighted L2 norm of `kappa_f - kappa_exact` on the active faces (`snGrad(alpha)` not zero). The app assembles `kappa_f` exactly as the solver's force path does. The ellipse gate takes the local exact value at each face centre ([`leiaTestMeanCurvature.C`](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/test/leiaTestMeanCurvature/leiaTestMeanCurvature.C#L13-L58), [`faceCurvatureEllipse2D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/faceCurvatureEllipse2D.yaml#L29-L32)).
2. Gain: `G = norm2(d kappa_f) / normInf(d psi)` for the perturbation `psi + eps h r`, with `r` a pseudo-random field in [-1, 1] and alpha held fixed. The gate reports `G h^2`: 1 means as sensitive as a second difference of psi ([`leiaTestCurvatureNoiseGain.C`](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/test/leiaTestCurvatureNoiseGain/leiaTestCurvatureNoiseGain.C#L11-L57)). The gain is constant to about 3 percent over N = 64 to 256 and linear in `eps` over a range of 100 ([PCS 10](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L743-L745)).

**What each gate can see.** A circle or a sphere has a constant curvature and a parallel foliation, so an averaging error and the foliation residual `D` are both zero there ([`faceCurvatureEllipse2D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/faceCurvatureEllipse2D.yaml#L3-L16), [PCS 11.2](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L832-L839)). The signed-distance ellipse adds a varying curvature and keeps `D = 0`. The quadratic-form ellipse has an exact fit and `D` not zero, so it measures the inverse's model error alone ([`faceCurvatureEllipsoidPsi2D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/faceCurvatureEllipsoidPsi2D.yaml#L5-L19)). The sphere adds the Gaussian curvature K. The weakest hypothesis of the inverse is a parallel foliation, not a signed distance ([PCS 11.1](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L792-L796), [[concepts/cell-centre-inverse-curvature]]).

## Why it matters

A static gate evaluates the curvature once per resolution, where a coupled run takes thousands of steps. The gates reject a candidate delivery before any coupled run ([STATUS 1](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L329-L331)). But accuracy alone ranks deliveries wrongly. Over three deliveries the static L2 error fell `45.8 -> 1.67 -> 1.18` 1/m while the coupled blow-up time fell `0.0803 -> 0.0668 -> 0.0202` s ([PCS 10](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L725-L729)). The gain orders the same three deliveries correctly and does not predict the magnitude of the growth ([PCS 10](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L737-L751), [STATUS 1](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L322-L327)). So the criterion asks for both numbers, and on a geometry that is not simpler than the interfaces the method runs on ([PCS 12](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L1056-L1062)). The stationary droplet cannot show the averaging defect, by construction ([PCS 12](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L1035-L1042), [[cases/stationary-droplet]]).

## Why it failed, or why we think so

Two families of delivery failed the ellipse gate. The cut-cell and the cell-mean deliveries assign one value to every active face of a cut cell. Where the curvature varies along the interface, each face then receives a value centred on the cell, an offset of `O(h dkappa/ds)`. That is first order by construction, and better averaging cannot repair it ([PCS 12](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L1020-L1028)). The symmetric face mean is symmetric in geometry but restricted to active faces. The active mask depends on the interface position in the cell, so the mean is offset at `O(h)` too ([PCS 14.1](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L1137-L1142)). Every construction that lowered `G h^2` below the per-face value lost an order on the ellipse. Within face-value averaging, a lower gain always cost an order ([PCS 14.1](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L1147-L1150), [[concepts/face-curvature-deliveries]]).

## Decisions

- The acceptance criterion: `G h^2 <= 0.65` and fitted L2 order `>= 1.9` on the ellipse gate, not on the circle; a candidate that meets only the order is a regression ([STATUS 7](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L2703-L2706), [PCS 12](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/plan-curvature-stabilization.md#L1044-L1047)).
- The cut-cell family is retired; the cell-mean adoption is retracted ([STATUS 1](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L348-L352), [[retractions/cell-mean-delivery-adoption]]).
- `CURVATURE_INVERSE_GAUSSIAN yes`, decided on the sphere gate ([METHOD 8.1](https://github.com/leia-openfoam/leia/blob/d1e3414/METHOD.md#L401), [[decisions/curvature-inverse-gaussian]]).
- Before 2026-09-01 the per-face inverse `stabilizedFootPointFace` was production and the only delivery that passed; since c935883 production is `cellCentreInverse` ([STATUS 1](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L341-L346), [[decisions/curvature-extension-cell-centre-inverse]]).

## Open questions

2. The ellipsoid gate and its polyhedral twin have no recorded result in STATUS, METHOD, the plans, the roadmap or the articles.
3. The 3D torus companion and the psi-transform arm `psi -> psi (1 + b cos(m theta))` are not built ([STATUS 7](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L2687-L2693)).
4. The SL article's text gives `O(h^1.2)` and 35 % to 1 % for the circle, and explains the first order by the `O(h)` Hessian of a quadratic fit ([SL article `sec:curvature`](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/semi-lagrangian-level-set/sl-level-set-article/semiLagrangianLevelSet.tex#L1774-L1788)). The text probably quotes the N = 512 row from before the guard fix: 10.2 1/m is 1.0 % (HYPOTHESIS, [RM](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/capillary-level-set-research-roadmap.md#L1339-L1352)).

6. The gates run on one rank and see no processor seam. Coupled runs found the seam defect of the face delivery: each rank corrected its own side only ([RM](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/capillary-level-set-research-roadmap.md#L1397-L1409)).
