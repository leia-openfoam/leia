# Every case under cases/: one table

> Verdict (2026-09-29). At commit d1e3414, `cases/` holds 39 case directories (the table below, read from each case's files). Six are exact or unit gates, ten are kinematic transport cases and four are static interface gates. Eight are coupled droplet cases, seven are force-model variants and four are reference arms with other solvers. The workflow renders every case from its templates and the three `.parameter` layers ([CLAUDE.md](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L160-L168)). The method gates use five cases per dimension ([`methodGate2D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/gates/methodGate2D.yaml#L88-L166), [[concepts/method-gates]]). The advection regression set uses `2Dvortex` or `2Dtranslation` and `3Dshear` ([CLAUDE.md](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L583-L596), [[concepts/advection-regression-set]]). Four case setups were found wrong ([[concepts/wrong-setup-voids]]). The 2D translating mesh had no inlet and no outlet ([STATUS 0](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L14-L46)). The 3D translating case had no reference velocity ([STATUS 11.14](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L3734-L3741)). On the first polyhedral Popinet surface, cfMesh tilted wall faces into the flow ([STATUS 4](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L1756-L1786)). The oscillating droplet used an algebraic psi ([STATUS 11.4](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L3289-L3297)). A fifth was found on 2026-09-29: `2Dtranslation` ran a reversed flow until that day, so every earlier number of the case is void ([STATUS 11.19](https://github.com/leia-openfoam/leia/blob/aaa0a7dd/STATUS.md#L4176-L4182), [[retractions/reversed-2dtranslation]]).

## What it is

A case directory holds the OpenFOAM templates (`0.org`, `constant`, `system`) with `@!TOKEN!@` entries. Its `cases/<case>.parameter` file holds the per-case defaults, and `cases/<case>_poly.parameter` replaces it for `mesh: poly` ([README](https://github.com/leia-openfoam/leia/blob/d1e3414/workflow/README.md#L159-L164)). One study is one (case, mesh, mode), selected by `config/<study>.yaml` ([`config.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/config.yaml#L1-L17)). The unit and utility cases run outside the case sweep. The `utilities` rule runs `1DredistanceTest` and `2DgradTest` ([`Snakefile`](https://github.com/leia-openfoam/leia/blob/d1e3414/workflow/Snakefile#L666-L670)). Three `Allrun.sh` scripts run the unit gates.

The families, in the order of the table:

1. Exact and unit gates: a closed form or exact assertions, seconds to minutes.
2. Kinematic transport: a prescribed velocity, no force; the error is transport error alone ([[cases/kinematic-advection-cases]]).
3. Static interface gates: no flow; the redistancing and curvature estimators on a frozen interface ([[cases/curvature-static-gates]]).
4. Coupled two-phase droplets: the SL two-phase solver with the production method ([[cases/stationary-droplet]], [[cases/oscillating-droplet]], [[cases/translating-droplet]], [[cases/popinet-translating-droplet]]).
5. Force-model variants: a droplet case with one other surface-tension or curvature model ([[models/surface-tension-force]]).
6. Reference arms: the stationary droplet with `interFoam` or `interFlow` on the same mesh and time step.

## Why it matters

The research loop orders the rungs: exact-solution unit gates, static field gates, kinematic transport, well-balanced coupled gates, coupled 2D, coupled 3D and polyhedral ([CLAUDE.md](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L474-L487)). This table maps each case to its rung. A case with a closed form gives a true error; the others need a surrogate or a reference, and the table says which.
