# Viscosity: open items

> Verdict (2026-09-29). `VISCOSITY_FACE_MODEL alg_lin` is decided in 2D ([[decisions/viscosity-face-model-alg-lin]]); five items stay open. First, the three 3D droplet templates have no `viscosityFaceModel` entry, so they run the code default `geo_lin`, and the 3D gate records this as OPEN ([STATUS 11.13](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L3605), [`methodGate3D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/gates/methodGate3D.yaml#L46-L48), [`createFields.H`](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/solvers/leiaLevelSetTwoPhaseFoam/createFields.H#L92)). Second, the banner printed `alg_lin (default)` for that code default until the correction of 2026-09-28 ([`printMethodBanner.H`](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/solvers/leiaSemiLagrangianLevelSetTwoPhaseFoam/printMethodBanner.H#L138-L141)). Third, the 36-arm ladder ran on 4, 8 and 16 ranks on 2026-09-03, before the coupled-face fixes of 2026-09-27 ([`mufGrid2D_jump1000_N128.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/mufGrid2D_jump1000_N128.yaml#L41-L46)). Every SL two-phase result on more than one rank before that date carries the two seam defects, and which studies to re-run is an open author decision ([STATUS 11.14](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L3686-L3692), [[concepts/coupled-face-density-defect]]). Fourth, a geometric sharp `alpha_f` consistent with the interface plane is listed as untested, and the record has no design or run for it ([[hubs/viscosity]]). Fifth, a reading of the history on 2026-09-29 found two frozen-`muf` traps (DERIVED). The `mu_f interpolated` row of the SL article's viscous-term table was measured before the frozen-`muf` fix ([SL article](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/semi-lagrangian-level-set/sl-level-set-article/semiLagrangianLevelSet.tex#L805-L829), [commit 39e59b3](https://github.com/leia-openfoam/leia/commit/39e59b3)). The solver still freezes `mu_f` under the `interpolatedDensity` mass flux, which is the code default type ([`updateFaceDensity.H`](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/solvers/leiaSemiLagrangianLevelSetTwoPhaseFoam/updateFaceDensity.H#L10-L68)).

## What it is

The face viscosity `mu_f` is the coefficient of the implicit Laplacian and of the explicit transpose part of the viscous term ([`UEqn.H`](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/solvers/leiaLevelSetTwoPhaseFoam/UEqn.H#L36-L46)). It is a stored face field: `createFields.H` builds it once as `fvc::interpolate(mixture.mu())` ([`createFields.H`](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/solvers/leiaLevelSetTwoPhaseFoam/createFields.H#L114-L118)), and `faceViscosity.H` rebuilds it after each new interface ([`faceViscosity.H`](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/solvers/leiaSemiLagrangianLevelSetTwoPhaseFoam/faceViscosity.H#L30-L88)). The six models are in [[models/viscosity-face-model]]. This note lists what the record leaves open after the 2D decision.

## Why it matters

1. The 3D gate would run a model that is not the 2D best, and a sweep cannot correct it. The workflow replaces only the `@!TOKEN!@` placeholders that a template contains, so a token without a placeholder has no effect (DERIVED, [`materialize.py`](https://github.com/leia-openfoam/leia/blob/d1e3414/workflow/scripts/materialize.py#L47-L56), [`methodGate3D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/gates/methodGate3D.yaml#L46-L48)).
2. A frozen `mu_f` shows in no banner and in no error column. The first frozen-`muf` bug made `alg_lin` look destructive and moved the default to `geo_lin` for a short time ([`cases/default.parameter`](https://github.com/leia-openfoam/leia/blob/d1e3414/cases/default.parameter#L758-L763)).
3. The 2D decision rests on one ladder, so its provenance sets how far the decision holds.

## Why it failed, or why we think so

The frozen-`muf` class has one cause: `mu_f` is a stored field, built once and rebuilt only inside a guarded block. Every guard that skips the block freezes it without a message. Before 39e59b3 the guard was the choice of a geometric model ([`cases/default.parameter`](https://github.com/leia-openfoam/leia/blob/d1e3414/cases/default.parameter#L758-L763)); at d1e3414 the guard is the mass-flux type and the frozen-`rhoPhi` switch ([`updateFaceDensity.H`](https://github.com/leia-openfoam/leia/blob/d1e3414/applications/solvers/leiaSemiLagrangianLevelSetTwoPhaseFoam/updateFaceDensity.H#L10)). The Eulerian solver had the same defect until c094bd8 ([[concepts/eulerian-solver-mass-flux-port]]). This is a reading of the code (DERIVED); no run with `interpolatedDensity` and a viscosity jump is recorded.

## Decisions

- `alg_lin` stays the 2D default until a re-run says otherwise ([[decisions/viscosity-face-model-alg-lin]], [[hubs/viscosity]]).
- The 3D templates need the token before the 3D gate runs ([`methodGate3D.yaml`](https://github.com/leia-openfoam/leia/blob/d1e3414/config/gates/methodGate3D.yaml#L47-L48)).
- Which parallel studies before 2026-09-27 to re-run or void is an open author decision ([STATUS 11.14](https://github.com/leia-openfoam/leia/blob/d1e3414/STATUS.md#L3689-L3692)).

## Open questions

1. The 3D token. A token that renders the global default `alg_lin` changes every 3D droplet case from `geo_lin` to `alg_lin`, so it is not inert and needs its own 3D measurement ([CLAUDE.md](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L764-L773)).
2. The ladder. A re-run after 28d13f0 and b1798c3, with the seam check and with the gate configuration (`cellCentreInverse`, the gate horizon), would show whether the decision holds ([[concepts/seam-checks-and-decomposition-invariance]]).
3. The geometric sharp `alpha_f` consistent with the interface plane. The record does not define it further. The nearest facts follow. The `geo_` models use the plane of the donor cell only. The article concludes that the consistency of `mu_f` with `rho_f` is not what limits the viscous term ([SL article](https://github.com/leia-openfoam/leia/blob/d1e3414/docs/semi-lagrangian-level-set/sl-level-set-article/semiLagrangianLevelSet.tex#L851-L853)). The symmetric `averagedPlanes` fraction is void and diverged ([[concepts/alphaf-source-donor-plane]]).
4. The article's viscous-term table. Its `mu_f interpolated` row and the claims built on it need a re-measurement on a post-fix binary or a retraction, by the retraction rule ([CLAUDE.md](https://github.com/leia-openfoam/leia/blob/d1e3414/CLAUDE.md#L751-L762)). The geometric and harmonic rows rebuilt `mu_f` at 4267d7b, but a setup wrong in one way is not assumed wrong in one way only.
5. The frozen path. Building `mu_f` outside the mass-flux guard, or a stop for `interpolatedDensity` with a viscosity jump, would close it; either change needs the bit-identity gate on a committed case.
6. The two stale comments in `UEqn.H` and `faceViscosity.H` are not corrected at d1e3414.
